# Security boundaries

The MVP is for a trusted private friend group. Broadcast sender identities are not cryptographically authenticated. Strict Zod schemas and host phase/actor/connection guards reject malformed input but cannot stop a malicious client impersonating another client. Public full-state snapshots expose owners and drafts in DevTools; anonymity is a UI filter, not confidentiality. No game persistence, analytics or secret credentials. Only VITE_SUPABASE_URL and VITE_SUPABASE_PUBLISHABLE_KEY may be supplied.

Supabase connects lazily only for room actions. M3 loads no YouTube resource before the submission panel's separate embedding consent: metadata, iframe API, nocookie frame and thumbnail are all gated. Consent is local to this mounted tab and is not persisted. Privacy-enhanced embeds still process third-party data and are not tracking-free. Vercel installs CSP, strict-origin-when-cross-origin Referrer policy and nosniff. `connect-src` permits self and the exact HTTPS/WSS project origins for `xbslarvipodajdvaxrwe.supabase.co`, never a wildcard. Changing the project requires matching header changes. Browser configuration accepts only an HTTPS URL and `sb_publishable_` key; configuration/storage failures do not create a usable fallback identity. Inline styles are allowed for React/Motion; inline scripts are not.

`/api/time` is GET/no-store. `/api/oembed` accepts one schema-valid video ID, constructs a fixed HTTPS YouTube URL, refuses redirects, has a five-second timeout and returns only schema-validated text/thumbnail metadata; arbitrary URLs and provider HTML never reach a fetch/render path. The IFrame API verifies actual current-video playback/duration before a submission is enabled. This is a browser UX validation, not server-side proof against a malicious client. The host still validates the Media wire schema and command phase/binding; accepted full-state/private-friend boundaries remain unchanged.

M2 validates room/epoch/sender/connection roles before accepting authoritative state, migration replicas, handoffs, results or ACKs. Only the designated bound replica acknowledges a new snapshot. Commands and state requests need bounded host-side rate limits; fragments need pre-allocation sender authority and bounded per-sender assembly, not merely eventual schema validation. Invalid or conflicting frames never become partial game state. Reassembly expires after five seconds without new unique valid progress; duplicates do not extend it, and the 128-part/6-MiB bound remains. See ADR-002.

Neither server ACK nor replica ACK promises durable persistence. A delayed Presence leave, suspended browser or network partition can exceed AK-4/5's five-second target. Recovery uses the highest surviving complete old snapshot; without one the session is lost, never rebuilt with empty data. Frame pacing is a per-room burst bound, not a guarantee for the project's shared quota. Phase 2 moves authority to a server and transmits only filtered views.
